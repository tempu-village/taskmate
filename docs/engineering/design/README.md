# Internal design

Read the relevant [Feature](../features/README.md) before changing user-observable behavior or feature-specific processing.

- [Architecture](architecture.md): components and dependency boundaries.
- [Data model](data-model.md): concepts, ownership and internal model relationships.
- [Security](security.md): trust boundaries and data access.
- [Testing](testing.md): evidence, commands, manual scenarios and known gaps.
- [ADR](../adr/README.md): accepted choices and trade-offs.

These records are shared by human developers and AI. Feature-specific behavior, processing, failures and verification belong together in the relevant Feature document. Strict shared formats and constraints belong in Specifications.
