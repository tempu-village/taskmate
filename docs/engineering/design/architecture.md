# Architecture

Status: Current implementation map.

## Components

[main.ts](../../../src/main.ts) owns plugin startup, settings, commands and Vault event subscriptions. It constructs Task/Project repositories and refreshes views when managed files change. [settings.ts](../../../src/settings.ts) owns plugin settings; source indexing and machine-local Vault registration are not implemented.

Source files are grouped by product capability rather than by layer; a folder may hold Domain, Persistence Adapter and UI Adapter files together. `src/tasks/` holds Task types, Markdown representation, edit merging, date suggestions, the Task repository, and failure collection for writes across several Tasks. `src/projects/` holds Project Markdown, persistence and the Project modal. `src/labels/` holds Label normalization and recent-label suggestions, management and picker models, Label rename and removal across Tasks, and their modals; editors pass Label data to the picker through its `LabelEditingOptions`. `src/task-editor/` holds the Task, Step and conflict modals and the Task editing flow that opens them, saves edits, resolves conflicts and deletes from the editor. `src/task-list/` holds the TaskMate ItemView, list model and renderer, filters, multi-selection state, scroll preservation and bulk editing. `src/shared/` holds the mobile keyboard layout used by both editors and bulk editing, and the SHA-256 helper used by both review kinds. `src/i18n/` owns translation catalogs, and `src/reviews/` is described below. Folder dependencies run `task-list → task-editor → labels / projects → tasks`, with `reviews → tasks`; a folder may skip levels, `tasks` imports no other feature folder, and any folder may use `i18n` or `shared`. The `task-list`, `reviews` and `settings.ts` references to `main.ts` are type-only. The [Module boundary test](../../../test/module-boundaries.test.ts) enforces these folder rules. Tests mirror these folders under `test/`.

[view.ts](../../../src/task-list/view.ts) is the Obsidian ItemView adapter. It loads domain data, owns navigation state, opens modals and dispatches persistence actions. Creating and editing a Task is delegated to [task-editing-flow.ts](../../../src/task-editor/task-editing-flow.ts), which receives the repositories, Label options, recent-Label recording and a refresh callback from the view. Writes that span several Tasks are delegated: [label-maintenance.ts](../../../src/labels/label-maintenance.ts) renames or removes a Label across Tasks and returns updated Label preferences, and [bulk-task-actions.ts](../../../src/task-list/bulk-task-actions.ts) applies bulk edits; both return the Tasks whose write failed, while the view keeps notices, settings persistence and selection updates. [task-filter-state.ts](../../../src/task-list/task-filter-state.ts) and [task-selection.ts](../../../src/task-list/task-selection.ts) hold the filter criteria and the multi-selection scope and selection that the view reads and updates. [task-list-model.ts](../../../src/task-list/task-list-model.ts) builds pure display sections; [task-list-renderer.ts](../../../src/task-list/task-list-renderer.ts) renders DOM and owns listeners/Sortable cleanup. Rendering emits intent; repository writes remain in the adapter/repositories.

[domain.ts](../../../src/tasks/domain.ts) owns Task/Project types and pure filtering, grouping and sorting. [repository.ts](../../../src/tasks/repository.ts) and [project-repository.ts](../../../src/projects/project-repository.ts) use public Obsidian APIs; [markdown.ts](../../../src/tasks/markdown.ts), [task-body.ts](../../../src/tasks/task-body.ts) and [project-markdown.ts](../../../src/projects/project-markdown.ts) handle portable representation.

`src/reviews/task-change/` is the Task change review feature Module. [proposal.ts](../../../src/reviews/task-change/proposal.ts) is its pure Domain implementation: it validates evidence, derives TaskMate-owned jsdiff hunks, checks exact patch replay and calculates approved writes and follow-up Proposals. Its stale guard compares complete Markdown, so a concurrent `rank` update from Manual order is preserved by returning a regenerated follow-up rather than merging a write against the old snapshot. [proposal-repository.ts](../../../src/reviews/task-change/proposal-repository.ts) is the Persistence Adapter for pending/history Vault storage and stale-checked writes. [review-renderer.ts](../../../src/reviews/task-change/review-renderer.ts) owns DOM rendering and emits review intent without persistence; [review-scroll.ts](../../../src/reviews/task-change/review-scroll.ts) preserves list position; [review-view.ts](../../../src/reviews/task-change/review-view.ts) is the Obsidian UI Adapter and coordinates the concrete repository, renderer and ItemView lifecycle on desktop and mobile. The protocol handler in `main.ts` accepts stable identifiers and can reveal a review but cannot approve or write.

The dependency direction is `main.ts → review-view.ts → proposal-repository.ts / review-renderer.ts / review-scroll.ts`, with the repository and renderer depending on `proposal.ts`. The pure Proposal Domain depends on the existing Task/Markdown Domain but not on Obsidian, DOM, or Vault. The type-only `review-view.ts → main.ts` reference is erased at runtime. No `reviews/shared` Module exists because only one implemented review kind currently proves common semantics; a future review kind can be added as a sibling without changing the Task change Proposal Domain. [Module boundaries](module-boundaries.md) owns the dependency and Interface rules that this map applies.

`src/reviews/source-candidate/` is the Source candidate review feature Module ([#61](https://github.com/tempu-village/taskmate/issues/61)). So far it contains only [proposal.ts](../../../src/reviews/source-candidate/proposal.ts), its pure Domain: it validates the versioned Source candidate Proposal against the RFC 0033 contract, verifies merge evidence, and calculates candidate edits, decisions, application results, review status and health, formal-apply eligibility, and Source-note completion. No Persistence or UI Adapter uses it yet.

Task Pilot, the [portable agent skill](../../../skills/taskpilot/SKILL.md), runs separately in an agent host. Its Python helpers operate on the same Markdown contract; they are not bundled plugin runtime dependencies.

## Change boundaries

Use browser/public Obsidian APIs in plugin runtime; Node/Python belong to build and external tooling. Preserve renderer teardown on rerender/close. Update both Markdown writers when changing a format, using [data ownership](data-model.md). Consult [source import](../features/source-import.md) or [edit conflicts](../features/edit-conflicts.md) when changing those flows.

## Evidence

[Model tests](../../../test/task-list/task-list-model.test.ts), [renderer tests](../../../test/task-list/task-list-renderer.test.ts) and [mobile layout tests](../../../test/mobile-layout.test.ts) cover selected boundaries. [Module boundary tests](../../../test/module-boundaries.test.ts) cover runtime import cycles and the folder dependency rules. Device verification remains separate.

[Proposal tests](../../../test/reviews/task-change/proposal.test.ts), [Proposal repository tests](../../../test/reviews/task-change/proposal-repository.test.ts), [review renderer tests](../../../test/reviews/task-change/review-renderer.test.ts), and [review Module boundary tests](../../../test/reviews/review-module-boundaries.test.ts) cover deterministic evidence, partial approval, isolated stale/write failures, history/follow-up persistence, DOM intent, and forbidden dependencies between review Modules. Task Pilot tests cover macOS, Windows, and Linux URI dispatch without invoking a shell. [Source candidate Domain tests](../../../test/reviews/source-candidate/proposal.test.ts) and [Schema tests](../../../test/reviews/source-candidate/schema.test.ts) check the RFC 0033 example, validation, transitions and Source-note completion, and validate every written state against the Draft 2020-12 Schema with the development-only `ajv` package. The macOS direct-URI spike is manual evidence; fresh Windows/Linux URI delivery and mobile visual verification remain gaps.
